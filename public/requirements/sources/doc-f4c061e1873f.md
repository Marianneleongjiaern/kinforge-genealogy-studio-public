# KinForge Mac build and installation

## What is supplied

KinForge-Mac-Build-Kit-0.3.1.zip contains a Swift/WebKit host, the bundled local web app, Info.plist and Build-and-Install.command. It is source/build material, not a compiled Mac application, DMG or PKG.

The development environment is Linux. The script has been shell-syntax checked, but Swift compilation, Mac launch, signing, notarisation, DMG mounting and installation have not been executed here. Do not treat this kit as a tested Mac release.

## On a Mac

1. Extract the kit. Xcode Command Line Tools are required; install them through Apple's normal xcode-select --install workflow if needed.
2. Run Build-and-Install.command. It compiles arm64 and x86_64 binaries, combines them with lipo, and uses Apple's pkgbuild and hdiutil to produce genuine packages.
3. The output is a timestamped folder inside your Mac's Downloads folder. It contains KinForge-0.3.1.dmg, a PKG, the app and checksums.
4. The command offers installation into /Applications. An existing app is not overwritten automatically. Use the generated installer after backing up existing data to replace an older app deliberately.

## macOS build runner

The source archive now includes `.github/workflows/macos-build.yml`. Put the source in a GitHub repository with Actions enabled, then run **Build and check macOS packages** from its Actions page. The manual workflow selects `macos-15` and `macos-15-intel`, runs the JavaScript tests, compiles both architectures, and uploads DMG/PKG artifacts and validation logs. This workflow has been prepared but has not run: no GitHub repository or Mac runner is connected to this workspace.

`Verify-on-Mac.command OUTPUT_DIRECTORY` checks checksums, mounts the DMG read-only, verifies both CPU architectures and the ad-hoc signature, expands the PKG, launches a temporary copy of the app and checks its bundled asset server. It does not install over an existing application. These are smoke checks, not full interactive UI or installation tests. A failed job may upload diagnostic artifacts; only a successful build and check log counts as a passed smoke check.

For a Mac you operate directly, the same scripts work without GitHub. Set `KINFORGE_NONINTERACTIVE=1` to skip installation prompts and Finder, and optionally set `KINFORGE_OUTPUT_DIR` to a chosen output directory. Runtime genealogy features remain independent of GitHub.

Runner documentation: https://docs.github.com/en/actions/reference/runners/github-hosted-runners

The script does not disable Gatekeeper, clear quarantine flags, request credentials or alter macOS security policy. Without a Developer ID signature and notarisation, Gatekeeper may refuse the resulting app or installer. Follow Apple's normal development/distribution workflow rather than disabling protections.

## Distribution signing

Optional environment variables:

- KINFORGE_SIGN_IDENTITY: your configured Developer ID Application certificate.
- KINFORGE_INSTALLER_IDENTITY: your configured Developer ID Installer certificate.
- KINFORGE_NOTARY_PROFILE: an existing keychain profile for notarytool.

Without these, the executable receives a local ad-hoc signature and the PKG remains unsigned. This does not establish a trusted publisher. A shared production release needs signing, notarisation and clean-machine testing.

## Data and runtime

The Mac host serves only bundled static assets on 127.0.0.1:49783. Family data remains in the WebKit local archive; the server exposes no archive API. A stable port is required for storage identity. If another process occupies that port, the app stops with an error rather than switching origins and appearing to lose the archive.

Downloads use the macOS Save panel, initially pointing at Downloads. Uploaded files use the Open panel. The host supplies native alerts, confirmations and printing. These bridges require Mac validation.

The user interface is WebKit-based with a native Swift shell, not a complete pure-Cocoa implementation of Ideas.md. The Mac archive and hosted-web archive are separate. Transfer with the full ZIP backup/restore workflow. Backups contain private data and are not encrypted.

## Workspace folders versus your Mac

The release bundle is staged in this workspace's Downloads folder and the build kit in its Applications folder. Those are not your Mac's actual ~/Downloads or /Applications directories; this environment cannot install onto your Mac. Only the command running on your Mac can create the DMG/PKG there and install the compiled app.
