# MacFamilyTree 11: Feature Coverage and Deep-Inspection Ledger

Observed on 23 September 2026 in the installed Mac application, using its supplied Sample Tree. This consolidates the direct observations made in this conversation. It is a reference for KinForge, not a claim that either application's entire feature set has been tested.

## Current Status

**The exhaustive inspection is not complete.** The walkthrough reached the main editing, chart, view, report, list, publishing and maintenance areas. Many outputs were rendered and several interactions were exercised. Individual option combinations, persistence, export fidelity, preferences, backups and connected-account workflows remain partly or wholly untested.

Computer control failed while leaving the source-template inspector and attempting to inspect duplicates. Subsequent connection attempts failed, and the Computer tool was unavailable in the following request. No successful duplicate-screen observation or final window cleanup can be claimed. The last verified screen was **Edit Source Templates > Short Citation**. The current app state must be checked when control returns.

The sample contained 123 people, 41 families, 70 places, 3 sources, 92 media entries, one person group, no stories and no ToDos. Empty sample sections limit what can be learned without a separate test tree.

### Operating Boundaries

- Use sample or explicitly disposable test data for experiments, not the user's private family records.
- Do not publish, upload, connect providers, accept terms or change credentials merely to inspect an interface.
- Inspect destructive maintenance options separately from executing them. Deletion, merging, restore and bulk rewrites need a recoverable test environment and appropriate confirmation.
- Keep observed behavior separate from inference, product recommendations and KinForge implementation status.
- Native screenshots were viewed in the conversation. They have not been saved as a screenshot bundle by this ledger.
- The earlier walkthrough discloses an accidental blank event that was immediately undone and verified. The later whole-product pass did not intentionally modify genealogical records or apply maintenance operations.

## 11. Deep-Inspection Protocol for the Next Pass

For each feature, record the following before marking its inspection complete:

1. Entry point, surrounding navigation, selected-record context and all visible subviews.
2. Every tab, menu, inspector section, setting and meaningful disabled state.
3. Input types, defaults/current values, optional fields, validation and empty-state behavior.
4. Selection, search, filtering, sorting, zoom, focus and navigation behavior as applicable.
5. A representative operation on an isolated test tree, with before/after evidence.
6. Save, close and reopen where persistence is part of the feature; explicit cancellation where no change is intended.
7. Output verification, including preview versus export, privacy, citations, media and date precision.
8. Error/recovery behavior and keyboard/assistive-technology access.
9. Exact restrictions and untested edge cases, without upgrading a menu observation into a passed test.
10. The lesson for KinForge and the corresponding implementation/acceptance requirement, kept separate from competitor behavior.

Immediate order on reconnection: verify/dismiss the current source-template sheet without changes; finish maintenance inspectors; inspect all preferences and menus; inspect ToDo Wizard and story/book/website authoring in disposable data; revisit incomplete maps; exercise 3D movement and slideshow; then inspect every chart/report/list option and save/export workflow.

## 12. Lessons for KinForge

These are design and test targets, not newly completed implementation:

- Build distinct, connected workspaces rather than a single static page. Preserve tree/person/event/source identity across views.
- Separate record editing from chart/document presentation. Both need explicit saved, unsaved and error states.
- Support quick inline edits and full evidence editors that share the same records.
- Treat sources as reusable records and citations as claim-specific evidence with locators, notes and certainty.
- Model parentage per parent-child link, and relationship history as dated, sourced events.
- Preserve uncertain and partial dates without inventing missing days or months.
- Make maintenance changes previewable and reversible, with conflict review rather than silent merging.
- Use clear privacy choices in every chart, report, export and publication path, especially for living people and sensitive attributes.
- Validate data, visual rendering and persisted/exported output independently. A partially loaded map or a visible export button is not a passed workflow.
- Use an original, consistent glyph system with labels and accessible alternatives. Do not copy proprietary artwork or imply clinical meaning without user-provided data.
- Keep the supplied Ideas.md as the complete KinForge requirement baseline. This reference does not replace its custom features or establish web/PWA/DMG/EXE/website parity.
