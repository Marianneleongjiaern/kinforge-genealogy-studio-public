6. Do not publish or connect online services as part of this local test. Any account-linked operation has its own authorization boundary.

## Import Boundaries

The fixture uses GEDCOM 5.5.1 because that version was explicitly visible in the inspected MacFamilyTree export menu. Compatibility is still unverified until an actual import. The format's family-level pedigree values do not provide a standard `step` value or a complete modern relationship model. Therefore Ellis's intended step relationship is documented for native testing rather than falsely encoded as birth/adoption; Jules and Lee use person associations until their native family is created. These are fixture decisions based on the [GEDCOM 5.5.1 specification](https://gedcom.io/specifications/ged551.pdf), not claims that MacFamilyTree lacks those features.

Separation and accessibility preferences are typed generic events in this file. Twin status is described in notes alongside matching dates. Native mapping, glyph assignment, per-parent semantics, Story/ToDo objects and privacy interpretation must be observed in the app. Neither restriction tags nor fictional living status prove automatic output suppression.

## Validation Boundary

The file was parsed using the independent [read-gedcom library](https://github.com/arbre-app/read-gedcom). Additional assertions check counts, reference resolution, reciprocal family links, dates and intended fixture cases. That is structural validation, not full GEDCOM schema certification, successful MacFamilyTree import, saved native data or passed app behavior.
