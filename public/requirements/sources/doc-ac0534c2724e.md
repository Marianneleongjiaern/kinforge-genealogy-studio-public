# MacFamilyTree 11: Symbol Reference for KinForge

Observed on 23 September 2026 in the installed MacFamilyTree 11 demo, using its supplied Sample Tree. This is a design reference, not an implementation or test-completion claim for KinForge.

## Evidence and Limits

- Inspected the Interactive Tree, gender menu, rendered Genogram, chart-style controls, person-event menu, family-event type table and built-in manual.
- Descriptions below identify the visible shapes beside labelled controls. They are not extracted icon assets or pixel-exact reproductions.
- Screenshots were viewed in the conversation. This document is the written reference, not a saved screenshot bundle.
- The built-in manual's section 19.16, Genogram (displayed page 363), explicitly identifies circles for women and squares for men. Other mappings below come from labelled interface controls or are identified as inference.
- A menu-scroll click accidentally added one blank LDS Endowment event to the sample person. Edit > Undo immediately reversed it. The original Events (9) was restored and verified again after closing the family-event type inspector. No type definitions, icon assignments or private family records were changed.
- Unknown/intersex genogram shapes, adoption/foster/custody connectors, medical notation and DNA notation were not verified. Do not infer their meaning from resemblance to symbols in another system.

## 5. KinForge Design and Test Targets

These are proposed acceptance criteria derived from observation. They have **not been implemented or tested by this research pass**.

1. Maintain separate categories for person notation, relationship notation, event icons, research/status badges and interface actions. Do not let a decorative style change alter the stored meaning of a record.
2. Provide an accessible, chart-specific legend. Show text labels or accessible names and tooltips, not color alone. Printed and exported charts need their own readable legend.
3. Keep the same event identity and recognizable icon across the person timeline, inline editor, full event editor, chart options and report output.
4. Use explicit labels for unknown, unrecorded and user-defined identity values. Do not assign an unverified shape or collapse distinct values just to match a competitor's menu.
5. Define and document each relationship connector before using it. Biological, adoptive, foster, guardian, step, partner and other supported links need data-model and rendering tests, not only different line styles.
6. Treat sensitive medical, DNA, government, custody and criminal-history annotations as controlled data. A symbol must not imply a diagnosis, legal finding or biological relationship unsupported by the record and evidence.
7. Support user-defined event types with a stable identifier, a name, an optional icon and a readable fallback. Preserve meaning when an icon is unavailable in an export or on another platform.
8. Use an independently designed or appropriately licensed icon set for KinForge. Study MacFamilyTree's conventions without copying its proprietary artwork or branding.
9. Test gender/person states, living/deceased markers, event types, custom-type fallback, chart selection and each relationship type independently. Include uncertain dates and conflicting evidence.
10. Test keyboard access, screen-reader names, enlarged text, high contrast, grayscale output, zoomed-out charts and mobile layouts. Check that marks remain legible without obscuring names or dates.
11. Verify that web, installed web app, macOS, Windows and exported reports preserve the same symbol meanings. Keep unverified platforms explicitly unfinished.
