# KinForge: Generations and Kinship Reports

Requested 23 September 2026. Scope: the existing local-first development preview, not a claim that every report type or release target is complete.

## User Requirement

"In the app I should be able to add parents before and after, so I can add generations before and add generations after. And on the report it should show maternal, paternal, how many generations removed, e.g 2nd cousin third generation removed, when the report is generated, it should explain how to read like 1st cousin 3 generations removed means what, and stuff like that."

## Acceptance Criteria

1. Select any person and add a parent above or a child below. Repeat to add grandparents, great-grandparents, grandchildren and later generations, including after descendants already exist.
2. Link an existing parent without duplicating the person. Preserve explicitly recorded co-parents and do not infer parenthood from a union.
3. New people remain visible when added from ancestor/descendant filtered views. Generation alignment and centred family branching continue to use the established layout rules.
4. Record Mother, Father, or Parent (side not recorded) on each parent-child relationship. Existing records remain unspecified unless edited. Never infer roles from gender, names or family colour.
5. A Kinship Report has a reference person and one comparison person or all other people in the tree. State relationships from the reference person's point of view.
6. Calculate direct ancestors, descendants, siblings, aunts/uncles, nieces/nephews and cousins. Cousin degree is the smaller generation distance to a closest shared ancestor minus one; removal is the difference between the distances.
7. Show maternal/paternal/unknown sides, shared ancestors, named parentward paths, generation distances and the direction of removal. Keep equally close first-parent routes, including both recorded sides.
8. Explain cousin terminology inside the generated report, including first cousins three times removed (2 versus 5 steps) and second cousins three times removed (3 versus 6 steps). Removal is not an age gap.
9. Keep spouse, partner, guardian and independently recorded sibling relationships separate from calculated ancestry. A social connection is not proof of ancestry. Do not claim full/half sibling or biological status from incomplete parent records.
10. Detect reachable ancestry cycles and report them without inventing results. Exclude cross-tree links and missing people. No recorded connection is not proof that people are unrelated.
11. Hide private names by default, including intermediate ancestors; allow explicit inclusion. All-person reports exclude private targets by default.
12. Retain report explanations in editable drafts and Text, RTF, PDF and CSV exports. Kinship CSV contains numbered report lines, including the glossary, rather than the unrelated people-directory export.
13. Save parent roles in the app's normal local state and JSON backups. Editing roles supports undo/redo. This change does not claim full GEDCOM role round-trip coverage.

## Follow-up: Plain Explanations and Editable Report Pages

The user requested explanations in both Person and Kinship reports, using the actual people's names. Once means one family generation apart, twice two, thrice three, and later removals keep counting parent-child steps. Show the intermediate cousin or ancestor and explain the direction. Cousin degree is distinct from removal. A cousin-in-law is a marriage connection, not an extra generation. Preserve recorded separation/divorce/end status and do not invent a marriage from a partner link.

The user requested the MacFamilyTree Person Report's whole visual style, with slight KinForge differences, including while editing. The official MacFamilyTree 11.1 English manual was downloaded and its printed pages 374 and 377 and editing examples around 409-411 were rendered and inspected. The observed report uses a portrait/title header with a turquoise rule, compact sans-serif body text, pale aqua section bands and a white document surface. This is visual reference evidence, not a fresh live Computer walkthrough.

The user also requested profile photographs and form-like editing. The chosen profile image is used in person-centred report headers. Labelled Person Report values can be edited in place while the report stays formatted. These edits change the draft, not the underlying genealogy records. Existing photographs remain local; no external image service is used. Drafts retain formatting, images and page-size settings through local saves and backups. Text and CSV are text-only formats; PDF and RTF carry images, with RTF a reflowable document rather than a pixel-identical page.

Regression coverage now includes the named explanation in both report types, cousin degree/removal in both directions, in-law paths and ended marriages, portrait selection, form-field isolation, formatting, undo/redo, saved snapshots, privacy, multi-page PDF output and responsive layout. See the report catalogue document for the expanded report list.

## Follow-up: Named Family Sides and Cousin Numbers

- Person and Kinship reports explain a maternal or paternal connection by naming the reference person's recorded mother or father. If that role is missing, the report names the recorded parent and states that the side is not recorded. Equally close routes through both sides retain both explanations.
- Each cousin explanation names the shared ancestor and the corresponding same-generation cousins, explaining why they are first, second or third cousins independently of the number of generations removed. The guide includes first and second cousins three times removed in both directions.
- Explanations use the report's existing privacy rules for parents, intermediate cousins and shared ancestors. New drafts include the changes; existing edited drafts are not overwritten.
- Regression coverage includes first, second and third cousins with zero through five removals in both directions, named sides, private intermediaries, formatted Person/Kinship drafts and exports. The browser generation workflow adds descendants first and then earlier ancestors, checking ordering and saved parent roles after reload.
